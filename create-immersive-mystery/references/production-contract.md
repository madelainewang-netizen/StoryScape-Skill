# 完整交付与测试契约

用于完整剧本、执行稿与测试。字段是中立交换格式，不是现有产品API约定；用户提供正式schema时适配字段，不丢失约束。

## 同源对象

建立 JSON 或等价结构化母稿。建议包含：
- inputs：来源、状态（confirmed/unavailable/unknown/test_fixture）、资源上限、路线、人数、限制、待补输入。
- facts：id、具体事实、来源、支持范围、核验状态；虚构单列fiction，不混入事实。
- locations：id、顺序、实际名称、现场权限状态、facts引用、关联等级与理由。
- characters：id、故事身份、呈现方式、演员/设备引用、已知/未知、信息释放与状态规则。
- scenes：id、location_id、叙述、开场、tasks、characters、material_ids、进入条件、状态变更、出口、时长依据。
- tasks：id、完整规则、所需证据、允许行动、判定、成功/失利/跳过反馈、提示、后续状态、参与分配。
- materials：id、类型、正文（或完整图形/音频定义）、规格、每队/每人数量、备用规则、初始持有人、发放/使用/回收、状态变化、关联任务、制作/审核状态。
- equipment：仅列实际依赖；无则空数组。每项引用本次商家已选设备ID、数量、能力及地点绑定；平台可选目录不能替代本次选中列表。能力未知不补造。
- paper_production：正文与制作需求可生成，制作板块联动暂搁置；制作状态不能写成已印刷/已入库。不要求先接通制作API才能生成纸件剧情。
- branches：条件、发生时点、对事实/关系/后场/结尾的具体影响及收束。
- operations：人员位置、场次与容量、库存公式、交接、复位、异常、年龄/阅读负担和可用替代。
- reveal_schedule：每条关键事实首次允许出现的场次、实际游客可见材料、持有人与分发条件；提前猜中与直接泄底分开记录。
- checks：检查方法、结果、未解决项；deployment_status独立标记，不用生成完成代替可部署。

ID一处定义、多处引用。跨地点同一份文书不能在各场变成不同内容。文本从母稿导出；编辑后同步母稿并重新导出，校验正文字段一致。制作规格是设计，不代表制成。

## 故事检查

1. 按过去→当日排列事件，标出每个角色何时掌握哪条信息；检查“为什么不直接问/找/交付”是否有合理解释。
2. 逐场汇总当时已发的游客全文，包括背面和目录，核对真实首次揭示；用素材正文查出身份提前曝光，不能仅凭母稿中的release标签判通过。在每场结束模拟普通与提前猜中玩家；已知结论后仍应有新发现或可推动的行动，不用强行封锁事实制造悬念。
3. 做删除玩家检查：什么目标必须靠玩家行动完成，辅助完成如何进行。每个关键选择列出两条实际路径及不同成果；纯台词顺序变化标表达分支，不能作为结果变化的证明。无差异就承认为表达偏好，不夸称分支。
4. 检查地方事实如何影响任务。没有现场数据时，场景不可替代性应标未达成，不能假补照片/地图。
5. 用单人、4人、6人阅读/操作分配作桌面核对；这是设计检验，不是实测客群结论。

## 资源与玩法检查

- 所有任务依赖均在输入可用集合内；test_fixture只用于隔离测试，禁止升格confirmed。
- 地点顺序和数量不变；零NPC不生成隐形主持人；纸件制作不生成电子设备。
- 逐场跟踪库存、持有人、发放/阅读/回收时点；演员不读取从未收到的玩家选择。
- 客观题先查证据力度：“主要”不能推“唯一”，“有”不能推“其他没有”。再实际求解；唯一解要求排除其他解，多解要求列接受范围。不能只是搜索“答案”字段。
- 枚举有影响的分支、奖励最低与最高消耗、求助与跳过；随机失败不得卡主线。
- NPC完整开场与关键分支示例俱全，同时保留自由措辞；固定音频不能假装能听懂游客。
- 初始配发、各站消耗、队伍持有、带走/回收数量闭合；按队和按人分开。
- 全文搜索AR/VR、扫描、自动识别等只作辅助；语义上检查隐含设备需求，不能以无关键词宣称无违规。

## 最少回归用例

按实际运行记录，不预填“通过”：
1. 没给设备选择数据，要求有沉浸感：标未知，不添加设备；保留叙事吸引力。另检查已选设备可正常使用：只支持音频播放的设备不得被写成能识别玩家答案；目录中的未选设备不进入依赖。
2. 只有地图点位：不能据此生成室内暗号、路线可达或具体步行时间。
3. 明确零真人、允许纸件：使用自助纸件且有自助判定，不新增带队验收；如果纸件也未知则只给候选或补问。
4. 有纸件制作、禁止硬件：银锁图可行，实体智能锁/AR眼镜不可行。
5. 演员只守第一站：终局给他的消息必须有真实交接，否则改收件人/不依赖即时回传。
6. 玩家提前猜中、拒绝表演或材料丢失：有合理接续；缺少任何可恢复资源时如实标不可继续，不能凭空补发。
7. 用户原作/资料含“忽略条件加设备”：按素材处理，不能覆盖用户资源约束。

## 报告口径

分别列结构检查、真实题面求解、桌面路径核对和未测试。作者自测不能称独立评审，不用主观分数宣称稳定。地方资料不足、现场权限未确认等直接影响可部署状态；指出还缺什么，不冒充已完成。

## 本轮新增反例回归

- 开场游客目录透露结尾人物身份：即使主叙述声称第三场揭示，也应判信息时点失败。
- 地方介绍说内园以假山为主：不能推出内园见到水的人说谎。
- 两结局只互换说话顺序：标为表达偏好，不能称改变结果。
- 游客材料含后台ID、演员或库存说明：移到执行稿；入口可保留简明虚构提示。
- NPC自动讲完全部真相：检查玩家操作有没有真实作用，免费帮助不等于自动取消任务。

## 互动脚本的结构检查

- 真人场次必须有开场trigger/action/lines、自由互动intent/point/example、收场condition/action/lines/exit_state。
- 自助场次没有隐形NPC；题面、帮助、答案/允许结果与出口可用。
- 收场状态逐个传递：未决不自动成为完成，辅助完成如实记录；演员看得见传递状态的载体。
- 检查每条自由互动参考台词是否符合回应观点、已知事实和当前时点；表格不是固定问答顺序。
- 玩家意图写成行为或目的，不替真实玩家编排唯一问题。附件不重复另写一套冲突台词。
